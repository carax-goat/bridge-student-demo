# whose side? — VS Code용 통합 디자인 데모

**제품명은 whose side?, 제작 팀은 Bridge입니다.**

학생 화면과 선생님 화면을 한곳에서 확인하는 HTML/CSS/JavaScript 디자인 데모입니다. 기존 서비스에 적용하기 전에 UI·UX와 진행 흐름을 검토하는 용도입니다.

- [온라인 디자인 데모](https://bridge-student-design-261112.brouto5942.chatgpt.site/#entrance)
- [참고한 기존 서비스](https://yunan-henna.vercel.app/)

## VS Code에서 실행하기

1. 이 저장소를 내려받거나 복제합니다.
2. 저장소 루트의 `whose-side-demo.code-workspace`를 VS Code로 엽니다. 또는 이 `vscode-demo` 폴더 자체를 엽니다.
3. Node.js 20 이상이 설치되어 있는지 `node --version`으로 확인합니다.
4. 이 폴더에서 아래 명령을 실행합니다. 외부 npm 패키지나 API 키는 필요하지 않습니다.

```sh
npm run check
npm start
```

[http://127.0.0.1:4173/#entrance](http://127.0.0.1:4173/#entrance)를 브라우저에서 엽니다. 종료는 터미널에서 `Ctrl+C`입니다. VS Code의 실행 및 디버그에서 **whose side? 로컬 데모**를 실행해도 됩니다.

저장소 전체를 연 터미널이라면 먼저 `cd vscode-demo`를 실행하세요. ZIP으로 내려받았다면 압축을 풀고 그 안의 `vscode-demo` 폴더를 여세요.

4173번 포트를 사용 중이면 PowerShell에서 `$env:PORT=4174; npm start` 또는 macOS/Linux에서 `PORT=4174 npm start`로 실행할 수 있습니다.

선생님이 일반 방을 만들면 시연 코드는 `WS2046`입니다. 예시 학생을 입장시킨 뒤 수업을 시작합니다. 방을 만들지 않은 학생 기본 입장 코드는 `BR2046`입니다.

## 유지할 제품 규칙과 디자인

- 학생의 진짜 생각과 가까운 역할을 **1순위·2순위**로 선택합니다. 클릭과 드래그를 모두 지원합니다. 끌기 손잡이는 터치 포인터도 처리합니다.
- 데모 배정은 1순위, 남은 자리에 2순위 순서입니다. 두 순위 모두 미배정되면 역할 전환자가 되어 **선택하지 않은 역할**을 맡습니다. 동순위 충돌은 입장 순서로 처리합니다.
- 현재 데모는 역할별 기본 한 자리로 계산합니다. 참고 서비스의 실제 중복 역할 배정 정책과 완전히 동일한 엔진은 아닙니다. 실제 서비스에 연결할 때 배정 정책을 확인하세요.
- **찬반 팀을 별도로 나누거나 찬반 버튼을 선택하지 않습니다.** 배정받은 역할의 목표·걱정·관점이 발언의 근거가 됩니다.
- 상세 역할 데이터는 기존 모의 게임의 **과제와 생성형 AI** 주제에 있는 5개 역할을 참고했습니다. 다른 주제를 선택해도 상세 카드·발언·요약은 이 디자인 검토용 예시입니다.
- 희망 순위와 비밀 정체는 다른 참가자에게 공개하지 않습니다. 정체는 결과에서 공개합니다.
- 흰색·연한 회색, 절제된 파랑, 읽기 쉬운 글자, 일관된 여백과 단색 픽토그램을 사용합니다.
- 노트북은 데스크톱 웹, iPad·Galaxy Tab은 터치 중심 모바일 레이아웃으로 확인합니다. 기기 미리보기와 실제 화면 너비가 함께 레이아웃에 반영됩니다.
- 모션은 짧은 전환·선택 피드백에 한정합니다. 운영체제의 `prefers-reduced-motion`과 화면 하단 **동작 줄이기** 설정을 지원합니다.

## 구현 범위

이 파일 묶음은 서버 없는 수정 데모입니다. 학생·선생님 설정, 시간, 안내는 **같은 브라우저** 안에서 연결됩니다. 다른 기기의 실시간 입장, 실제 마이크·음성인식·AI, 인증·데이터베이스는 구현되어 있지 않습니다. 모둠의 발언 횟수와 요약은 예시입니다. 개인 메모·회고와 수업 설정은 브라우저 저장소에 남습니다. 화면 상단 **데모 처음으로**로 초기화할 수 있습니다.
